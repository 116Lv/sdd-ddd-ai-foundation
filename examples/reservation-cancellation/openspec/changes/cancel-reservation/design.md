# 취소 처리 설계

## 경계와 책임

인증 계층은 인증된 회원 식별자를 전달하고 예약 경계가 `docs/domain/cancellation-policy.md`의 R-01~R-03을 집행한다. 요청 처리기는 인증된 회원, 예약 식별자, 요청 키를 받고 결과 또는 거절 사유를 반환한다. 저장소 제품 선정은 `docs/project/profile.md`에서 관리한다.

## 결정과 실패 처리

예약 상태, 취소 이력과 요청 결과를 같은 트랜잭션에서 기록한다. 요청 키는 회원과 예약의 조합 안에서 유일해야 한다. 동시에 도착한 같은 키의 요청은 기존 커밋 결과를 조회한다. 서로 다른 키의 동시 변경은 확정 상태인지 조건부로 갱신한다. 저장 실패 시 전체 작업을 취소하므로 같은 키로 재시도할 수 있다. 별도의 결제·알림 호출은 없다.

## 검증 접근

[작업 목록](tasks.md)에서 각 인수 조건의 관찰 지점을 확인한다. 구현 시 저장 실패와 경합을 재현해 상태·이력·결과 기록을 함께 확인한다.

## 미정 사항

요청 키 보관 기간이 지나면 같은 키를 새 요청으로 볼지 결정해야 한다. 정책 담당자와 보관 기간·만료 후 반환값을 정한 뒤 AC-004의 시간 경계와 저장소 정리 방법을 보완한다.
