# 프로젝트 시작 안내

프로젝트를 시작할 때 아래 순서로 작성한다. 기능을 추가하거나 동작을 바꿀 때는 [기능 변경 절차](workflow.md)를 반복한다.

1. [프로젝트 소개](../README.md)에 이름과 한 줄 설명을 적고, [제품 개요](../docs/product/brief.md)에 해결할 문제, 사용자, 목표, 성공 기준과 첫 출시 범위를 정리한다.
2. DDD 관점에서 사용자가 쓰는 업무 용어와 핵심 흐름을 찾는다. [용어집](../docs/domain/glossary.md)에 합의한 의미를 남기고, 설계에 필요한 규칙·경계·책임·상태를 관련 도메인 문서로 정리한다. 첫 기능에 필요한 깊이부터 시작한다.
3. [프로젝트 설정](../docs/project/profile.md)에 기술 선택과 개발·검토 기준을 기록한다. 결정 전인 값은 `미정`으로 두고, 기능 구현이나 검증에 영향이 있는 항목을 작업 전에 확인한다.
4. OpenSpec을 프로젝트에 초기화하고 첫 기능 변경을 작성한다. 기획과 도메인 문서를 참조하여 관찰 가능한 동작을 명세하고, 설계·작업·구현·검증을 그 명세에 연결한다.

## 파일 소유

| 경로 | 역할 |
|---|---|
| `.foundation/` | 기반 버전에서 제공하는 안내·양식·검토 기준·도구 |
| `foundation.lock.json` | 관리 도구가 기록하는 기반 버전·파일 해시·AI 연결 정보 |
| 루트 `AGENTS.md`, `README.md`, `CONTRIBUTING.md`와 `docs/`, `contracts/`, `openspec/` | 프로젝트의 기획, 규칙, 계약과 명세. 시작 문서는 한 번 생성하며 이후 프로젝트가 편집한다. |
| AI 도구별로 추가하는 진입 파일과 스킬 연결본 | 선택한 도구의 연결 절차로 생성·갱신하는 파일 |

프로젝트별 규칙은 프로젝트 설정에 작성한다. 기반 업데이트 시 관리 파일의 지역 수정과 새 버전 차이를 확인한 뒤 수동으로 반영한다. 정책과 기록의 원본 위치는 [프로젝트 문서 지도](../docs/README.md)에서 찾는다.
