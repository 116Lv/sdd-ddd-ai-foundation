# 변경 완료 검토 체크리스트

구현한 변경이 인수 조건을 충족하는지 확인한다. [변경 절차](../workflow.md), [프로젝트 설정](../../docs/project/profile.md), 변경의 명세·작업 목록과 실제 증거를 함께 확인한다.

## 공통 확인

- [ ] 변경 이름과 검토한 변경본(브랜치, 커밋 등)을 확인했다.
- [ ] 명세의 모든 인수 조건을 열거하고 관련 구현과 실제 검증 결과를 대조했다.
- [ ] 인수 조건마다 `AC ID / 상태(충족·미충족·미검증) / 증거 / 남은 문제`를 남겼다. 증거는 무엇을 확인했는지와 결과를 볼 수 있는 위치를 함께 적었다.
- [ ] 체크한 작업, 문서 검사, 테스트 실행 결과를 각각 근거가 뒷받침하는 범위에서 기록했다.
- [ ] 실패하거나 실행하지 않은 검증에 대해 남은 문제와 필요한 확인을 기록했다. 미충족이나 미검증 인수 조건이 있으면 전체 완료를 보류한다.

## 변경에 해당할 때 확인

- [ ] 계약 호환성, 데이터 전환, 운영 절차 등 변경 범위에 필요한 검증 결과를 확인했다.
- [ ] 배포가 검토 범위에 있으면 대상 환경, 실행 결과와 증거를 기록했다. 배포 전 변경 검토라면 배포 상태를 따로 적었다.

PR·CI에 증거를 연결한다. PR을 쓰지 않는 경우 [검증 기록 양식](../templates/verification.md)을 사용한다.
